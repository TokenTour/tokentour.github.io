    设计语言参考

    这一页是 TokenTour 设计语言的唯一事实来源，也是组件用法参考。 每个组件都给出「实时示例 + 可直接复制的代码」。要做新主题时，照着这里的写法用即可， 不要另起一套样式。底色乳白、主色青、强调橙——文字应该像被印出来的，不是被发光的。

    给后续 agent 的说明

    组件都在 src/components/，设计 token（颜色 / 字体）都在 src/styles/design.css 的 :root 里，用 var(--color-*) 取用。 交互组件（Accordion / Tabs）是 Astro 组件，自带 <script>，零额外接线； 图表是 React island，必须带 client:* 指令。新增颜色 / 间距时优先复用既有 token， 不要硬编码十六进制。

    文字

    正文走衬线：--font-serif 首选 思源宋体（Noto Serif SC）， 经 Google Fonts 加载，离线回落到系统宋体（Songti SC / STSong）。代码用 --font-mono。 正文字重 500，加粗是 700（跨两档才够明显）；标题与正文同族，仅靠字号字重区隔。

    可以用 超链接（默认无下划线，hover 才有）提示更深的内容；行内的 chat_template、术语像 prefill / decode，以及快捷键 ⌘K 各占其位。

    三级标题，节奏的最小单元

    h2 上方留较宽的呼吸，h3 跟得更紧——一段长文应自然形成几个被命名的台阶， 而不是一连串小标题密集穿插。

    列表

    • 无序列表用最细的圆点，不使用方块或 emoji。
    • 支持嵌套：
      • 第二层换成空心？暂时先保持一致。
      • 真正的层级感应该靠缩进和留白。
    • 列表项内可以混排 code 与强调，不会破坏行距。
    1. 有序列表的数字用 oldstyle figures，更像正文。
    2. 第二步。
    3. 第三步——通常包含一段相对长的解释，比如「为什么这个步骤要放在前面」， 说明完成之后接下一步。

    引用

    阅读的舒适度，八成来自字体与留白，剩下两成来自配色。 那两成里，一成来自背景不是纯白。

    代码 · CodeBlock

    块级代码用 <CodeBlock>：Shiki 在 build 时渲染 github-light 主题（零运行时）， Carbon 风格标题栏带红绿灯圆点与复制按钮。行内代码直接写 <code>。

    按钮 · .btn

    纯 CSS class，无需组件：基类 .btn + 一个语义修饰类。主操作用青、强调用橙； 按下去会陷下去（硬阴影、不偏移布局）。disabled 走原生属性。

    标签 · .badge

    软底色药丸，用于状态 / 元信息。默认无彩，彩色版与语义色一一对应。

    表单控件 · .field / .choice

    纯 CSS class，无需组件，沿用按钮的「印在纸上」风格：1.5px 边 + 细硬阴影，聚焦时描边变青、外加一圈淡青。 单选 / 多选是按钮式 chip（.choice），选中填淡青；内部圆点（单选）或对勾（多选）让单选 vs 多选一眼可辨。

    旁注 · Callout

    带 lucide 图标的旁注。type 决定配色与图标，title 可省略。 语义约定：primary 最常用（定义 / 关键概念），accent 给「动手 / 易踩坑」， 其余对应成功 / 警告 / 失败——彩色要克制，别让全文花花绿绿。

    无标题：仅靠淡灰底色与正文区分，正文直接铺满。用于补充信息。
    定义 青色旁注用于「定义、关键概念、链接到 playground」。是文中最常出现的彩色块。
    动手试试 橙色旁注用于「需要读者动手 / 容易踩坑」。
    通过 成功 / 通过 / 已完成态。
    注意 警告 / 副作用 / 数据将被修改。
    危险 失败 / 不可逆 / 安全相关。看见即提高警觉。

    折叠 · Accordion

    一个组件 = 一个可折叠块。底层是原生 <details>（键盘 / 页内查找都在）， 展开时正文像小票被打印出来（WAAPI 驱动，自带 <script>，无需接线）。 连续放多个会自动贴紧成一组。

    什么是 KV cache？

    解码每生成一个 token 都要重新做一次 attention。把过去步骤的 key / value 缓存下来、 复用而不重算，就是 KV cache。代价是显存随上下文线性增长。

    为什么不同模型有不同 chat template？

    训练时见过什么格式，推理时就只认什么格式。Qwen、Llama、DeepSeek 的特殊 token 与拼接顺序都不一样； chat_template 把结构化 messages 编译成那个模型熟悉的纯文本。本质是一段 Jinja 模板。

    分词器到底在做什么？

    把字符序列切成子词单元（subword），再映射成整数 id。常见算法有 BPE、WordPiece、Unigram； 同一句话在不同分词器下的 id 序列没有任何可比性。

    标签页 · Tabs

    labels 给标签文字，面板用编号 slot（"0"、"1"…）按顺序对应。 active 标签下方有青色滑动下划线（弹性缓动）；禁用 JS 时第一个面板默认可见。

    图表 · Chart（React island）

    交互式可视化用 recharts，封装成 React island。下面这个以 KL 散度为例： 参考分布 P = N(0, 1) 固定，用滑块调 Q 的均值与方差，实时看 DKL​(P∥Q)=∑x​P(x)log2​Q(x)P(x)​ 怎么变，切换方向还能直观感受它的不对称性。 这同时是一个「内容即 skill」的范例——demo 本体已把概念讲清楚，后续 agent 可照搬这套 「图 + 控件 + 旁注」的结构去讲别的指标。

    DKL​(P∥Q)=2.337bits
    P=N(0,1)（参考分布，固定）Q=N(1.80,1.00)（可调）

    DKL​(P∥Q) 衡量「拿 Q 去编码真正来自 P 的样本，平均多花几 bit」。它恒 ≥0，且仅当 P=Q 时为 0。

    前向 KL D(P‖Q)：在「P 有质量、Q≈0」处代价爆炸，于是 Q 被逼着盖住 P 的整个支撑（mass-covering / 均值寻求）。最大似然与交叉熵训练最小化的就是它——P 是数据，Q 是模型。

    只平移均值、方差不变时，前向与反向 KL 恰好相等；不对称要靠改变形状才显现。

    目录 · Toc

    Notion 风格的浮动目录，钉在页面右侧边缘——就是你现在在这一页右边看到的那条。收起时是一列右对齐的短横， h3 比 h2 更短；当前所在小节的横条会变青、变长。鼠标移上去（或键盘聚焦），标题文字从裁切宽度里淡入、 横向「打印」出来（无卡片背景，直接浮在页面留白上）。组件零配置：脚本自动扫描页面里的 <h2> / <h3> 建立目录并接管滚动高亮，任何 .prose 页面直接放一个 <Toc /> 即可。视口太窄放不下侧栏时自动隐藏。

    键位

    快捷键样式：按 ⌘Enter 发送， Esc 取消编辑，/ 聚焦搜索。

    调色板

    每个色（primary / accent / success / warning / danger）都是 6 档色阶，命名向 Tailwind 看齐： 50 最浅，做页面 hint；100 做面板填充；300 做边框； 500 是品牌色本身，做 CTA；700 用于 hover / 在白底上的文字； 900 给「在 100 填充上的高对比文字」。
